1系统架构总览

整个平台由「通话数据面」和「管理面」两部分组成。UFI 设备既是 VoLTE 终端又是 SIP 网关，所有呼叫经 dSIPRouter（Kamailio）选路后与 VOS3000 交换。

图 1 · 通话数据面与管理面。UFI 经 SIP 注册到 dSIPRouter，管理台通过 HTTP 接口与设备交互。
组件职责本教程涉及页面 / 接口

dSIPRouter设备接入认证、线路池选路、呼入 dbaliases 映射、acc 呼叫日志通信管理 /ufi-callcenter

2前置条件清单

开工前逐项确认，任何一项缺失都会卡在后面的步骤：

  • UFI 设备已插入可用的 VoLTE SIM 卡（4G 可上网，信号 ≥ 中等）
  • 设备固件为 Linkcircle-UFI-C（支持 sip-setting / status-push / log 上报）
  • 设备所在网络可访问公网（能连到管理台域名）
  • 已知晓设备 IMEI（机身标签或设备启动日志可查）与 SIM 号码
  • 已登录管理台 https://ufi.mineo.top，能打开「UFI 设备」与「通信管理」两个页面
  • （联调阶段）VOS3000 管理权限，或已把 VOS 侧配置项列入客户指引单
💡
SIP 认证信息不用人工准备。系统约定：SIP 用户名 = SIM 号，密码 = MD5(IMEI) 前 16 位，SIP 服务器地址由管理台在 sip-setting 应答中自动下发，设备侧零配置。

3第一步：设备上电与自动纳管

UFI 的接入是「设备主动上报 → 服务端自动开户 → 默认配置回填」的全自动流程，人工只需在管理台确认结果。

图 2 · 新设备上电后的自动纳管时序。全程无需在设备端手动填写 SIP 服务器。
  1. 上电插卡：确认 SIM 卡在位、4G 联网成功（设备屏或指示灯）。
  2. 设备自动发起 sip-setting：设备带签名上报 IMEI / SIM 号；服务端校验签名后，若开启自动开户（auto_provision），即按 IMEI 创建 SIP 账号并回填 sipServerAddress / sipServerPort / sippassWord。
  3. 设备用下发参数完成 SIP 注册：Kamailio 侧出现 location 绑定，状态变为已注册。
  4. 心跳保活：设备按周期上报 status-push（信号、CPU、存储、SIP/VoLTE 状态等），服务端据此维护在线状态。
  5. 管理台确认：打开「UFI 设备」(/ufi)，新 IMEI 应出现在列表顶部，核心网状态满足下表。
检查项期望值不达标时
设备出现且「在线」在线查设备网络/管理台连通性，看第一步上报是否到达（Nginx/WAF 访问日志）
SIP 注册已注册确认 sip-setting 应答非空（首次注册即自动下发）；401 见附录签名机制
VoLTE在线SIM 未开通 VoLTE 或当地无覆盖，换卡/换位置
心跳保活正常超过 300s 离线会自动记入「指令与日志 → 设备异常事件」
buildNumber有版本号固件过旧，先升级固件再继续
⚠️
若列表里出现疑似重复/测试设备，可在设备监控中直接删除（会连同事件、短信、通话、日志文件一起清理，不可恢复）。

4第二步：通信管理配置（入池）

纳管成功的设备还要在「通信管理」(/ufi-callcenter) 里配置通信属性，才会参与线路池轮询选路。

操作路径

  1. 进入 通信管理 → UFI 通信配置，在列表找到新 IMEI（设备台账自动带出，只读）。
  2. 点击行内「编辑」，填写通信属性后保存即落库生效（写入 dsip_ufi_pool 表，无需重启）。
  3. 回到「线路总览」确认新线路出现在轮询池中，KPI 开始累计。
字段示例说明
sim13215946233SIM 号，即 SIP 用户名；也是呼入 dbaliases 的映射目标之一
pool_idP1线路池编号，同池按权重轮询；— 表示未入池
enabled1通信启用开关；停用后退出轮询池（呼入不受影响）
in_pool1是否参与选路；维护模式下可置 0 摘出流量
weight1 ~ 99池内权重，越大分到的话务越多
max_concurrent2并发上限（单 UFI 建议 ≤ 2）
noteUFI#4 新接入备注，方便多设备管理
💡
「UFI 通信配置」支持勾选多台后批量启停 / 转维护 / 清零并发计数；「变更任务」页保留两类任务：我方待办（如批量开户脚本）与客户指引单（VOS 侧配置的交接单），新设备如果只动本页配置，不需要生成任何待办。

5第三步：VOS3000 侧配置

这一步打通「dSIPRouter ↔ VOS3000」。分呼入、呼出两条，配置项在 VOS 管理界面（若 VOS 由客户管理，可直接在通信管理「变更任务」页生成指引单发给客户）。

图 3 · 呼入/呼出信令路径与 VOS 侧配置要点。
方向VOS 配置项要点
呼入话机管理 → 话机 1002 → DIDs末尾用英文逗号追加新 SIM 号；覆盖原有值会导致现有呼入中断
dSIPRouter → 号码与路由dbaliases 呼入映射（SIM 号 → 1002），设备 sip-setting 自动开户时已生成，确认存在即可
呼出网关管理 → 接入网关「dsip接入」认证方式 = IP 认证，IP = dSIPRouter 出口地址；呼出号段/Prefix 追加新 SIM 号（号段是授权白名单，不在白名单会被拒呼）
dSIPRouter 通信管理无需额外配置，线路池选路在第二步已就绪
⚠️
客户版 VOS 可能不开放网关菜单，需管理员权限；改完话务配置后按客户规范重载（reload）配置再验证。

7第五步：实测后的链路分析

测试完成后，进入「通信管理 → 线路总览 → 通话记录」，打开目标通话卡片。系统已把 UFI 侧日志（volte / sip）与 dSIPRouter 侧呼叫日志（route）三侧联合展示，一条通话的全过程无需跨系统翻日志。

图 4 · 通话卡片三侧联合展示。

分析步骤

  1. 先看结论列：通话卡片顶部有方向、状态（接通/未接）、时长与结果；失败时优先读 route 侧的响应码。
  2. 按段定位：用图 4 的分段法——route 侧无记录说明呼叫没进 Kamailio（查 VOS 授权/网络）；route 有 INVITE 但 sip 侧无 INVITE 说明 dSIPRouter→UFI 段断了（查设备在线与 dbaliases）；sip 侧有 INVITE 但 volte 侧不振铃查 SIM/VoLTE。
  3. 交叉验证采集日志：「采集日志」tab 可按 IMEI + 时间区间筛选设备上传的日志文件；下发「日志采集」指令后，响应里可直接点击跳转（自带 IMEI）。
  4. 查设备异常事件：「指令与日志 → 设备异常事件」记录心跳保活失败、SIP/VoLTE 掉线（含离线起止时间）、CPU 高负荷、存储紧张、SIM 锁定等，支持 IMEI + 时间区间检索——通话异常时段若与事件时间重合，根因基本锁定。
  5. 池级验证：改过权重/并发后重复 T3，确认分流比例符合 weight 预期。

分析结论怎么记

每个失败测试项按此格式回填到测试矩阵：

现象：T1 呼入无振铃（14:32 拨打）
定位：route 侧无 INVITE 记录；sip 侧无 INVITE；volte 侧无事件
结论：呼叫未到达 UFI —— VOS 话机 1002 DIDs 未含新 SIM 号
动作：VOS 侧追加 DIDs（指引单 #2）→ 重载 → 14:41 复测通过

9附录：认证与签名机制

SIP 账号约定

SIP 用户名
SIM 号（11 位手机号）
SIP 密码
MD5(IMEI) 的前 16 位（hex 小写），由服务端计算并在 sip-setting 应答中下发
SIP 服务器
sip_host : sip_port（默认 5060/UDP），sip-setting 自动下发
开户方式
auto_provision 开启时，设备首次 sip-setting 即自动创建 subscriber 账号

HTTP 接口签名

设备侧所有上报（sip-setting / status-push / log 等）都携带 sign 字段：对固定字段子集按 key 排序拼接后加 secret_key 做 SHA-256。要点：

  • 签名只覆盖固定字段子集，服务端与设备端保持同一跳过集合（当前 7 个：sign、encryptionType、mac、simOperator、operatorName、serviceCellBand、cellularSignalRsrp）
  • 自洽验证法：取设备日志中的 hash 原始串，本地复算 SHA-256 对比，能精确暴露「差哪个字段」
  • secret_key 存于 dsip_ufi_config 表（32 位），服务端与设备端必须一致
