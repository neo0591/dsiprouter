UFI 短信接口对接说明

UTF-8 · HTTP REST POST · ts + SHA-256 签名。发送、上行推送、状态推送与短信密文解密均按本说明实现。

发送：/ufi-app/api/ufi/sendSms 管理：短信中心 → 开放 API 联调：模拟对接页 · Postman 返回帮助中心

1. 概述

接口编码 UTF-8，请求方式 HTTP REST POST。每个接口需传递 ts、sign 做权限校验。

  • ts：调用时刻 unix 时间戳（毫秒）。服务器校验前后 5 分钟内合法，否则返回签名过期。
  • sign：按业务参数 + ts 计算的 SHA-256 签名。

2. 鉴权与签名

密钥在管理台「开放 API」配置（也可按运营商覆盖）：

密钥用途默认值（可改）
api_key标识调用方（可选放 Header / 体）097365176B381B00C4F3079A0D11E303
secret_key计算 / 校验 sign默认同 api_key（可单独设置）
sms_key推送 smsBody XOR 加解密902C4397DE9AD9ECA8F7A736FDAFA13D

Sign 生成

  1. 去掉 sign 字段后，按 JSON key 的 ASCII 升序拼接：k1=v1&k2=v2&...
  2. 末尾追加 &secret_key=xxxxx
  3. 对整串做 SHA-256，得到小写 hex 作为 sign
# 示例（伪代码）
agentType=LC-UFI-C&...&ts=1733827361936&wlanPassword=mysecurepassword&secret_key=123456
→ SHA-256 → sign
对齐 hutool SignUtil.signParams(SHA256, map, "&", "=", true, "&secret_key=", secretKey)。

3. 状态码

code说明
200成功
400请求参数错误或无效
401签名过期或无效
500系统错误

4. 发送短信

POST /ufi-app/api/ufi/sendSms（兼容 /api/v1/sms/sendSms、/api/ufi/sendSms）

字段必填说明
requestId是请求唯一标识
ts是unix 毫秒时间戳
sign是参数签名
callerNumber是发短信号码（用于选通道）
calleeNumber是收短信号码
text是短信内容

请求示例

{
  "requestId": "6aE41dB9-f421-e1C9-67EB-e692DfF7c5Ab",
  "ts": 1733827361936,
  "sign": "cba50e7ec9fe06c0ac5a937f7a580d8445dd83791dd95ab233f19744cbedcfda",
  "callerNumber": "13625000004",
  "calleeNumber": "15159900003",
  "text": "测试短信"
}

返回示例

{
  "requestId": "6aE41dB9-f421-e1C9-67EB-e692DfF7c5Ab",
  "ts": 1733827361936,
  "code": 200,
  "message": "发送成功"
}

5. 收短信推送（MO）

平台主动 POST 到运营商配置的「客户短信推送地址」。

字段说明
requestId本次上报唯一标识
smsId短信唯一标识
smsTypeinbox=收
smsBody密文，需用 sms_key 解密
smsTel / callerNumber对方号码
calleeNumber本机号码
smsTimestamp短信时间（毫秒）
ts / sign鉴权
{
  "requestId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "smsId": "10000899101",
  "smsType": "inbox",
  "smsBody": "1KKw3ZCb1KKk",
  "smsTel": "18909101001",
  "smsTimestamp": 1765280069127,
  "callerNumber": "18909101001",
  "calleeNumber": "13625000004",
  "failResult": "success",
  "ts": 1733827361936,
  "sign": "..."
}

客户侧应返回：

{ "smsId": "10000899101", "code": 200, "comment": "success" }

6. 短信状态推送

下行发送完成后，平台 POST 到「短信状态推送地址」。

字段说明
smsId短信标识（优先 requestId / ext_id）
smsTypeoutbox=发件
smsStatus0=成功，1=失败
failResult失败原因；成功通常为空
smsBody加密正文
callerNumber / calleeNumber发/收号码
ts / sign鉴权
{
  "requestId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "ts": 1753700000123,
  "smsId": "sms-20260728-0001",
  "smsType": "outbox",
  "failResult": "",
  "smsBody": "cba50e7ec9fe06c0a",
  "smsStatus": "0",
  "callerNumber": "+8613800138000",
  "calleeNumber": "+84936157034",
  "sign": "..."
}

7. 短信内容解密

smsBody 为 Base64(XOR(UTF-8 bytes, sms_key))。解密：Base64 → XOR → UTF-8。对齐 XorCipherUtil.xorCrypt(text, false, smsKey)。

默认 sms_key：902C4397DE9AD9ECA8F7A736FDAFA13D

8. 兼容接口（Bearer）

管理台内部 / 旧对接仍可用 Authorization: Bearer <api_key>：

方法路径说明
POST/api/v1/sms/send单发
POST/api/v1/sms/batch批量任务
GET/api/v1/sms/message/{id}查询
GET/api/v1/sms/health健康检查

9. 配置入口

  • 开放 API：维护 api_key / secret_key / sms_key
  • 通道与频控：按运营商配置 MO / 状态推送 URL 与密钥覆盖
密钥与推送地址修改后即时生效；此前因未配置而跳过的推送会自动重试（近 2 天）。
