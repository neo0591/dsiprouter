## 1. 访问入口

| 用途 | 地址 | 说明 |
|------|------|------|
| Web 管理台 | `https://106.75.29.22:5000/` | Nginx 反代到 Unix Socket；浏览器可能提示证书不受信任 |
| SSH | `ssh root@106.75.29.22` | 运维入口 |
| SIP | `UDP/TCP 5060`（公网 IP / 内网 IP） | Kamailio 信令 |
| MariaDB | `127.0.0.1:3306` | 仅本机，库名 `kamailio` |

- 管理台监听 **5000/HTTPS**，不是 80 端口。访问 `http://106.75.29.22/` 通常打不开或不是本服务。
- 用 HTTP 访问 5000 时，Nginx 会按配置引导到 HTTPS（`error_page 497`）。

## 2. 架构与依赖

```
浏览器 / API
    │ HTTPS :5000
    ▼
 nginx  (sites-enabled/dsiprouter.conf)
    │ proxy_pass → unix:/run/dsiprouter/dsiprouter.sock
    ▼
 dsiprouter.service  (User=dsiprouter)
    │ SQLAlchemy
    ▼
 mariadb  ←── kamailio.service  (SIP :5060)
```

关键 systemd 单元：

| 服务 | 作用 | 正常状态 |
|------|------|----------|
| `dsiprouter` | Flask GUI / API | active |
| `nginx` | HTTPS 反代 :5000 | active |
| `kamailio` | SIP 路由 | active |
| `mariadb` | 配置与 CDR（acc 等） | active |
| `docker` | 可选容器（如 Hermes） | active（非核心） |

启动顺序（unit 声明）：`network` → `mariadb` / `nginx` / `kamailio` → `dsiprouter`。

## 3. 关键路径

| 路径 | 说明 |
|------|------|
| `/opt/dsiprouter` | 项目代码（GUI、脚本、资源） |
| `/opt/dsiprouter/venv` | Python 虚拟环境 |
| `/etc/dsiprouter` | 系统配置、证书、Kamailio 片段 |
| `/etc/dsiprouter/gui/settings.py` | GUI 配置（含 DB、端口、API Token 等） |
| `/etc/dsiprouter/kamailio/kamailio.cfg` | Kamailio 主配置 |
| `/etc/dsiprouter/certs/` | TLS / STIR-SHAKEN 证书 |
| `/run/dsiprouter/dsiprouter.sock` | Nginx upstream |
| `/run/dsiprouter/dsiprouter.pid` | 进程 PID |
| `/dev/shm/shmem_*` | UltraDict 共享内存（**属主必须是 dsiprouter**） |
| `/var/log/dsiprouter.log` | GUI 日志（journal 更常用） |
| `/var/log/kamailio.log` | Kamailio 日志（体积可能很大） |
| `/var/log/nginx/error.log` | Nginx 错误日志 |

## 4. 日常运维命令

### 4.1 推荐：用 `dsiprouter` CLI

```bash
# 查看帮助
dsiprouter help

# 重启全部（GUI + Kamailio + RTPEngine 等，按安装组件）
dsiprouter restart -all

# 只重启 GUI
dsiprouter restart -dsip

# 只重启 Kamailio
dsiprouter restart -kam

# 停止 / 启动
dsiprouter stop -dsip
dsiprouter start -dsip

# 同步 Kamailio 配置（改完相关设置后）
dsiprouter configurekam
```

### 4.2 直接用 systemd

```bash
systemctl status dsiprouter nginx kamailio mariadb
systemctl restart dsiprouter
systemctl restart nginx
systemctl restart kamailio
systemctl restart mariadb   # 谨慎：影响 SIP/GUI 读库

# 启动失败被限流后先清状态再启
systemctl reset-failed dsiprouter
systemctl start dsiprouter
```

### 4.3 Kamailio 热重载（不重启进程）

```bash
kamcmd permissions.addressReload   # address 表 / IP 鉴权
kamcmd drouting.reload             # 动态路由 / 网关组
kamcmd core.version                # 版本探活
```

Web 界面「重载 Kamailio」也会触发类似同步。

### 4.4 健康检查

```bash
# 服务状态
systemctl is-active dsiprouter nginx kamailio mariadb

# 监听端口
ss -lntp | grep -E ':5000|:5060|:3306'

# Unix Socket 是否存在
ls -la /run/dsiprouter/

# HTTPS 探活（本机）
curl -sk -o /dev/null -w '%{http_code}\n' https://127.0.0.1:5000/

# 共享内存属主（必须是 dsiprouter，不能是 root）
ls -la /dev/shm/ | grep shmem
```

期望：`dsiprouter` / `nginx` / `kamailio` / `mariadb` 均为 `active`，`curl` 返回 `200`。

## 6. 常见故障

### 6.1 浏览器显示 `502 Bad Gateway`

含义：Nginx 在，**上游 dsiprouter 挂了或 Socket 不通**。

处理步骤：

```bash
systemctl status dsiprouter --no-pager -l
journalctl -u dsiprouter -n 80 --no-pager
ls -la /run/dsiprouter/dsiprouter.sock
```

若日志出现：

```text
PermissionError: [Errno 13] Permission denied: '/shmem_state'
# 或 '/shmem_state_memory'
```

原因：曾用 **root** 跑过导入 `settings` / `dsiprouter` 的 Python 脚本，在 `/dev/shm` 留下 root 属主的共享内存，服务用户 `dsiprouter` 无法覆盖。

修复：

```bash
systemctl stop dsiprouter
rm -f /dev/shm/shmem_state* /dev/shm/psm_*
systemctl reset-failed dsiprouter
systemctl start dsiprouter
sleep 2
systemctl is-active dsiprouter
curl -sk -o /dev/null -w '%{http_code}\n' https://127.0.0.1:5000/
```

**运维规范**：需要在服务器上跑 GUI 相关 Python 时，用：

```bash
sudo -u dsiprouter /opt/dsiprouter/venv/bin/python ...
```

避免直接 `root` + 导入 UltraDict / settings，防止再次污染 `/dev/shm`。

### 6.2 `dsiprouter` 启动失败：`Start request repeated too quickly`

```bash
systemctl reset-failed dsiprouter
# 先按 6.1 清 shmem（如有权限错误）
systemctl start dsiprouter
```

### 6.3 通话详单为空

常见原因：

1. 页面未选「全部通话 / All Calls」，仍按终端组过滤。
2. Kamailio `acc` 表无今日 INVITE/BYE（先查库）。
3. GUI 服务异常或读库失败。

快速核对：

```bash
mysql -ukamailio -p kamailio -e "SELECT COUNT(*) FROM acc WHERE method IN ('INVITE','BYE') AND time > UNIX_TIMESTAMP(CURDATE());"
systemctl is-active dsiprouter mariadb kamailio
```

### 6.4 话单里有运营商组名，Carrier Groups 页面没有

Carrier Groups 列表按 `dr_gw_lists.description` 匹配 `type:8`。  
若描述写成纯文本（如 `VOS3000 Carrier Group`）会被过滤；话单通过网关联表仍能显示名称。

规范描述示例：

```text
name:VOS3000 Carrier Group,type:8
```

网关描述示例：

```text
name:VOS3000 Carrier,type:8,gwgroup:100
```

修正后刷新页面即可；必要时：

```bash
kamcmd drouting.reload
kamcmd permissions.addressReload
```

### 6.5 改完代码 / 翻译不生效

1. 确认文件已同步到 `/opt/dsiprouter/...`
2. 翻译需编译 `.mo`：`python /opt/dsiprouter/gui/compile_translations.py`（或本机编译后 scp）
3. `systemctl restart dsiprouter`（注意不要用 root 先跑会碰 shmem 的脚本）
4. 浏览器强刷缓存

### 6.6 SIP 不通但 Web 正常

```bash
systemctl status kamailio
ss -lntp | grep 5060
tail -n 100 /var/log/kamailio.log
kamcmd core.version
# 安全组 / 云防火墙是否放行 UDP/TCP 5060
```

## 7. 配置与部署

### 7.1 从本机同步 GUI 改动（示例）

在开发机（PowerShell）常用模式：

```powershell
scp -P 22 .\gui\templates\xxx.html root@106.75.29.22:/opt/dsiprouter/gui/templates/
scp -P 22 .\gui\translations\zh\LC_MESSAGES\messages.mo root@106.75.29.22:/opt/dsiprouter/gui/translations/zh/LC_MESSAGES/
ssh -p 22 root@106.75.29.22 "systemctl restart dsiprouter; sleep 2; systemctl is-active dsiprouter"
```

重启前若刚用 root 跑过 Python 探测脚本，先按 **6.1** 清理 `/dev/shm`。

### 7.2 重要配置文件

- GUI：`/etc/dsiprouter/gui/settings.py`（多数改动需重启 `dsiprouter`）
- Nginx：`/etc/nginx/sites-enabled/dsiprouter.conf` → 改后 `nginx -t && systemctl reload nginx`
- Kamailio：`/etc/dsiprouter/kamailio/` → 可用 `dsiprouter configurekam` 或 `systemctl restart kamailio`

API Token、管理员密码等敏感信息用：

```bash
dsiprouter setcredentials -h
dsiprouter resetpassword -h
```

不要把 Token / 密码写进公开文档或提交 Git。

### 7.3 备份与恢复

```bash
dsiprouter backup -f /root/dsip-backup-$(date +%F).tar
# 恢复前确认版本兼容
dsiprouter restore -f /root/dsip-backup-YYYY-MM-DD.tar
```

建议同时备份 MariaDB：

```bash
mysqldump --single-transaction --routines --triggers kamailio > /root/kamailio-$(date +%F).sql
```

## 8. 排障检查清单（5 分钟）

按顺序执行：

1. `systemctl is-active dsiprouter nginx kamailio mariadb`
2. `curl -sk -o /dev/null -w '%{http_code}\n' https://127.0.0.1:5000/` → 期望 `200`
3. `ls -la /run/dsiprouter/dsiprouter.sock`
4. `ls -la /dev/shm/shmem_state*` → 属主应为 `dsiprouter`
5. `journalctl -u dsiprouter -n 50 --no-pager` 查 Traceback
6. SIP：`ss -lntp | grep 5060` + `kamcmd core.version`
7. 库：`mysql -ukamailio -p -e 'SELECT 1'`

## 9. 本机定制说明（与上游差异）

当前云端在上游基础上做过定制，运维时需知晓：

- 中文默认 i18n（`gui/i18n.py`、`gui/translations/zh/`）
- 许可证门禁已去掉（部分功能不再要求 license）
- CDR：支持「全部通话」、横向滚动；增强字段（呼叫方向、原始主被叫、挂机原因等）依赖 Kamailio `acc` 扩展字段与路由脚本
- 运营商组列表依赖 `description` 中的 `type:8` 格式

相关脚本/补丁示例：`resources/cdr_enrich_kamailio.sh`。

## 10. 紧急恢复（Web 502）

复制粘贴即可：

```bash
systemctl stop dsiprouter
rm -f /dev/shm/shmem_state* /dev/shm/psm_*
systemctl reset-failed dsiprouter
systemctl start dsiprouter
sleep 2
systemctl is-active dsiprouter
curl -sk -o /dev/null -w 'HTTP %{http_code}\n' https://127.0.0.1:5000/
journalctl -u dsiprouter -n 30 --no-pager
```

若仍失败，再查 MariaDB / Socket 权限 / `journalctl` 完整 Traceback。
